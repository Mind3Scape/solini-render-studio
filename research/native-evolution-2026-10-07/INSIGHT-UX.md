# Salini Inside — рабочий борт руководителя (Insight UX)

Ветка `codex/salini-native-materials`, база `65b34ea`. Реализация — Opus, дизайн-приёмка и QA — Codex. Демонстрационная модель: заказы, суммы и процессы условные, не продажи и не телеметрия Salini.

## Checkpoint 6.0 — дизайн-консультация

### Что меняется по сути

Сейчас вход открывает «всю компанию», сверху — три метрики, под ними подпись, внизу инструменты и док; проблема ищется вручную. Новый вход отвечает на один вопрос: **что сейчас требует меня и где это видно.**

### 1. Первые 3 секунды владельца

- **Кадр сразу на главной проблеме**, без пролёта от общего плана: фокус ставится в первой раскладке (`layoutSubviews` до первого кадра), как сейчас ставится квартал.
- Приоритет выбирает **детерминированный resolver** из `FactorySimulation` — один источник правды, без случайностей:
  1. **Блокирующая проблема** — останавливает поток прямо сейчас. Marea удержана на ОТК → рейс 02 не может выехать.
  2. **Срочность** — риск срыва с закрывающимся окном решения. Aria: прогноз 17:20 при плане 17:00, резерв F-04 можно подключить только до 15:50.
  3. **Загрузка** — самый загруженный участок, если решений нет.
  4. Иначе — **живой процесс**: рейс в пути, затем погрузка, затем производство.
- Каждый фокус несёт **причину одной строкой** и **доступ к решению**: «Marea · удержана ОТК · рейс 02 ждёт» → «Решить»; «Aria · +20 мин к плану · окно до 15:50» → «Решить».
- Почему Marea раньше Aria на старте: блок уже остановил отгрузку, а Aria — пока риск. После «Назначить повторный осмотр» первой станет Aria; после её решения — загрузка/живые процессы. Порядок виден и проверяем тестом.

### 2. Сколько сцены над бортом

- iPhone 18 Pro (402 × 874 pt): шапка ~60 pt под safe area, **борт ~176 pt** над домашним индикатором (карточки 116 + строка подробности 32 + отступы), **сцена ≈ 560 pt — около 64 % экрана** (сейчас ~45 % из-за метрик сверху, подписи, ряда инструментов и дока).
- Убираются дублирующие этажи: верхние три метрики, подпись «ТЕРРИТОРИЯ · …», отдельный ряд инструментов. Их содержимое переезжает:
  - метрики → карточки борта (один экземпляр каждой цифры);
  - «Вся территория», крыши, слои, участки, маршрут → меню «…» в шапке и тап по мини-карте;
  - масштаб ± → щипок, двойной тап, а для VoiceOver — custom actions «Приблизить / Отдалить / Вся территория».
- Мини-карта остаётся (маленькая, справа сверху под шапкой): ориентир и выход в общий план.

### 3. Свайп статистики против выбора фокуса

- **Свайп** по борту только листает карточки показателей. Камера не двигается, состояние не меняется.
- **Тап** по карточке выбирает её: карточка получает выделенное состояние, под рядом появляется **одна строка контекста** («Рейс 02 · Санкт-Петербург · в пути 12 мин»), камера **ведёт к соответствующему живому процессу**.
- **Повторный тап** по выбранной карточке или кнопка в строке контекста открывает панель решения / заказа / рейсов.
- Тап **никогда** не выпускает машину и не меняет бизнес-состояние: только камера и выделение.
- Карточки (из единой демо-модели `InsideBoard`):
  - **Решения** — число открытых решений (Marea, Aria) → resolver-фокус.
  - **Портфель смены** — сумма пяти фиксированных демо-заказов (₽), проверяемая агрегация → офис/заказы.
  - **В работе** — изделий на производстве (литьё → обработка → ОТК → упаковка) → участок, где сейчас самая крупная партия.
  - **Принято ОТК** — 42 / 68 → участок качества.
  - **Готово к отгрузке** — места на складе и в доках → погрузка (склад → док).
  - **В пути** — рейсы на маршруте → следование за машиной; после выезда за территорию — честное «в пути», камера у ворот.
- Выбор хранится по **стабильному id карточки**; обновление цифр перенастраивает ячейки на месте, без перезагрузки — ни выделение, ни прокрутка не сбрасываются.

### 4. Возврат к живому событию после ручного обзора

- Явная **политика камеры** вместо неявных флагов: `CameraMode`
  - `event(Focus)` — кадр на фокусе resolver или выбранной карточки, без следования;
  - `follow(Target)` — следование за движущимся якорем (машина рейса 01/02, погрузчик), кадр каждый тик;
  - `manual` — любое касание карты (pan, pinch, тап мини-карты, «Вся территория»);
  - `tour(index)` — маршрут Aria по этапам.
- В `manual` **никакие ревизии модели не переставляют камеру** (сейчас `refresh()` снова выбирает зону `trackedOrder` после ручного pan — это убирается).
- Пока есть выбранный фокус, в `manual` над бортом появляется капсула **«↺ К событию»**: возвращает в `event`/`follow` того же фокуса. Новый фокус resolver **не** перехватывает камеру в `manual` — борт отмечает изменение (бейдж на «Решения»), камера ждёт решения пользователя.
- Следование:
  - у **обоих рейсов** настоящий движущийся якорь (позиция машины в presentation-слое), слежение за рейсом 01 и рейсом 02;
  - если машина ещё в доке — кадр на доке со статусом «Погрузка / Готов к выезду»;
  - когда машина покидает территорию, камера останавливается на воротах, карточка показывает «В пути · <город>», а не пустой кадр.

### 5. Ограничения, которые сохраняются

- Изометрия строго фиксирована: меняются только фокус и масштаб.
- Reduce Motion: перелёты мгновенные, следование — скачком раз в такт без анимации, движение сцены по-прежнему останавливается; ценность сохраняется через выделение и текст.
- Пауза и уход в фон: часы, движение и следование стоят; при возврате кадр не прыгает.
- VoiceOver: карточки — кнопки с названием, значением и подсказкой «Двойное нажатие — показать на карте»; строка контекста — живая область (`.updatesFrequently` только для «В пути»); Dynamic Type: карточки растут по высоте, борт прокручивается, сцена уменьшается не больше чем до 50 %.
- Сохраняются: панели решений, заказов и рейсов, сценарии Aria / Marea, крыши, маршрут-тур, мини-карта.

### Тесты (план)

- **opening priority** — resolver на старте → Marea; после осмотра → Aria; после решения Aria → загрузка / живой процесс.
- **KPI consistency** — цифры борта = агрегации демо-заказов и `FactorySimulation` во всех переходах сценария.
- **manual survives revisions** — после ручного pan ревизии не меняют фокус камеры.
- **stat resumes tracking** — тап «В пути» → `follow` нужного рейса; «К событию» из `manual` возвращает тот же фокус.
- **оба рейса** — у рейсов 01 и 02 есть якорь и слежение; тап не выпускает машину.
- **выход за территорию** — после ухода машины кадр у ворот и статус «в пути».
- **pause / Reduce Motion** — в паузе фокус не меняется; при Reduce Motion установка мгновенная.

### Коррекция Codex к 6.0 (принята)

1. Живой процесс выше простой загрузки; загрузка — только последний запасной вариант. После решения камера сама не перескакивает между событиями.
2. Повторный тап по выбранной карточке в `manual` возвращает к событию; панель — только явной кнопкой «Решить» / «Подробнее», без скрытого двойного тапа.

5. Мини-карта даёт и территорию, и навигацию по участкам. Идентификаторы для QA.

## Checkpoint 6.2 — слежение за выбранным процессом (compile-ready, ждёт тестов и визуальной приёмки)

Коррекция Codex: «не прыгать» = не переключаться на ДРУГОЙ заказ, но вести ЭТОТ процесс.

- **Субъект процесса** (`InsideSubject`: заказ / рейс / участок) хранится в фокусе; текущая цель — `FactorySimulation.target(of:)`: Marea — ОТК (удержана, осмотр) → упаковка → **погрузчик** (`.transfer`, якорь `batchTransfer`) → машина рейса 02 в доке → в пути / ворота. Domino — машина рейса 02. Остальные заказы — их участок.
- В `event` / `follow` камера идёт за текущей целью выбранного субъекта при каждой ревизии; в `manual` меняется только текст (цель в строке уже новая), камера стоит. «К событию» и повторный тап ведут к **текущему** положению, не к старому ОТК.
- Фокус ищется по id + субъекту; другой заказ сам не подставляется. Исчезнувшее решение помечается один раз (`#taken`) и читается «Решение принято · <статус>»; у процессов («В работе») — просто текущий статус выбранного заказа.
- `trackedOrder` и маршрут заказа сохраняются для субъектов-заказов (раньше `showActiveFocus` их сбрасывал).
- Панель рейсов: «Выпустить рейс 01» → слежение за рейсом 01; «Выпустить рейс 02» → за рейсом 02 (`onTrip`), без изменения других решений.
- Камера: `follow(FollowAnchor)` — рейс или погрузчик; перелёт 0,85 с к движущемуся якорю больше не обрывается первым кадром слежения (ожидание до посадки, затем короткое догоняние 0,25 с; Reduce Motion — без анимации). `focusOn(_, mode:)` задаёт режим явно — после маршрута-тура режим возвращается в `event`. Смена раскладки (высоты борта) не снимает `manual`: ручной фокус и масштаб сохраняются.
- Тексты: «12 раковин ожидают повторного осмотра · рейс 02 не может выехать»; «Marea и Domino загружены · ожидает разрешения на выезд».
- Тесты (собраны, не запускались): `testChosenBatchIsFollowedAlongItsOwnRoute` (ОТК → упаковка → погрузчик → рейс 02, субъект не меняется), `testManualOnlyUpdatesTextAndReturnGoesToTheCurrentPosition`, `testReleasedTripFromThePanelIsFollowed`; обновлены ожидания прежних тестов под `follow(.trip(…))` и `#taken`.
- Проверено: `build-for-testing` (simulator) и `build` для устройства без подписи — успешны. Визуально и тестами не проверялось.

## Checkpoint 6.3 — полировка борта (compile-ready, код заморожен для QA)

Борт по-прежнему не выше половины экрана; если содержимое выше — борт прокручивается по вертикали, причина не обрезается. Выделение карточки — тонкая линия (1 pt, ink 28 %) вместо жирной рамки.

## Checkpoint 6.4 — три локальные правки (compile-ready, код заморожен)

QA 6.3: 8 из 9 целевых PASS; FAIL — `testBoardFitsANarrowScreenWithTheLargestText`, одна неоднозначная раскладка. Цепочка осмотр → погрузчик → рейс 02 и пауза подтверждены Codex в UI.

Проверка не ослаблена; при провале выводит тип, идентификатор и рамку каждого неоднозначного вида.
