## 0. Коротко

1. **Приложение сейчас — витрина из 4 товаров.** В аудите сайта 300 уникальных публичных карточек и 82 семейства по первому слову названия. Проход начинается не с материалов, а с **проверенного офлайн-каталога**: конвейер данных → поиск, фильтры, детальная карточка исполнения. Всё остальное (материалы, проект, PDF, Inside) опирается на этот каталог.
2. **Материалы:** одна реальная форма Salini из официальной USDZ, студийный свет, сравнение покрытий на **одной и той же** геометрии. Предлагаю не Greca: она продаётся только в S-Stone матовом, и показывать на ней глянец S-Sense было бы неправдой. Нужна модель, которая на сайте реально есть в обоих материалах: **Noemi 170** (S-Sense глянец / S-Stone матовый) — для главной; **Ornella / Cascata** (три исполнения: S-Sense глянец, S-Sense матовый, S-Stone матовый) — в полной студии.
3. **Проект → спецификация → персональное PDF-предложение:**
   - реальные выбранные позиции, исполнения, количества, цены и сроки по классу номенклатуры;
   - польза изделий и материалов — из официальных текстов;
   - цветовые этюды **именно выбранного** изделия: его собственная 3D-модель в цветах RAL, с честной пометкой «концептуальная визуализация».
4. **Шоурумы и помощь:**
   - 270 записей дилеров с координатами;
   - официальные контакты;
   - FAQ: уход, гарантия, сроки, доставка.

   Без ERP и без отправки заявок: «поделиться» через системное меню.
5. **Inside 2.0:**
   - **два производственных комплекса** и роботизированный участок (заявление бренда);
   - раздельные цепочки ванн, раковин, поддонов, столешниц, мебели и зеркал;
   - больше территории, дорог и осмысленного движения;

   Текущая причинно-следственная модель сохраняется и расширяется.
6. **Ведём 5 итераций с визуальной проверкой после каждой** (раздел 10). Первая — данные и каталог: без них материалы и PDF снова станут декорацией.

## 2. Диагноз текущего приложения

- **Каталог.** `Product.all` = Aria, Opera, Greca, Opera Top. Поиск, фильтры, проект и PDF работают только на них. Остальное приложение не масштабируется до реального ассортимента.
- **Материалы.** Две лаковые «шайбы»-образцы в пустоте. Форма придумана, к изделию не относится, свет условный. Выглядит как демонстрация шейдера, а не как вещь Salini. Слой «структуры» верен по фактам, но визуально беден.
- **PDF проекта** — текстовый чек без пользы изделий, без изображений и без вариантов цвета.
- **Inside** — один кампус из 9 условных корпусов в бледной палитре. Цепочки разных изделий не читаются, движения мало, это не «два комплекса и роботизированный участок».
- **Что сильное и сохраняется:**
  - фильмы коллекций;
  - роли, меняющие главную;
  - модель решений Inside (резерв F-04, повторный ОТК, выпуск рейса);
  - нативный UIKit и системное стекло;
  - честные подписи происхождения.

## 3. Архитектура продукта

### 3.1 Навигация (предложение)

Четыре вкладки для всех ролей, содержимое меняется по роли:

1. **Главная** — журнальная лента: фильмы коллекций, блок материалов, новинки 2026, ролевой блок действий.
2. **Каталог** — поиск, фильтры, категории, коллекции.
3. **Проект** — текущий проект, комплектация, спецификация, PDF-предложение. Позже — несколько проектов.
4. **Salini** — шоурумы и дилеры, контакты, помощь (уход, гарантия, сроки, доставка), о компании и награды; Inside — у владельца и в демо-режиме.

Студия материалов открывается из главной, из карточки изделия и из проекта — это функция, а не вкладка.

### 3.2 Модель данных (предложение, локальная, Codable)

```
Family     id, name, collectionId?, categoryPath, designer?, story, advantages[]   (факт: сайт/презентация)
Product    id (site product_id), familyId, name, installation, dims{L,W,H,depthToOverflow},
           variants[], documents[], media[], model3D?, sourceURL, snapshotDate
Variant    material(.sStone/.sSense/.mdf/.solidSurface/.gelcoat), finish(.matte/.gloss),
           sku, priceRub?, weightKg?, packedWeightKg?, availability(.stock(n)|.madeToOrder(class)|.unknown)
Showroom   id, name, address, coordinate, phones[], site?, hours?, hasExposition, type
Project    id, name, client?, rooms?, lines[], createdAt, updatedAt
Line       productId, variantSku, colour(RAL?|white), options[], quantity, note
Proposal   projectId, snapshot of lines+prices+texts, generatedAt   → PDF
```

**Правила:**
- цена, артикул и вес хранятся **на варианте**;
- срок хранится классом (`stock` / `order15` / `custom30` / `discontinued` / `onRequest`) и выводится с типом календаря;
- снимок даты показывается в карточке и в PDF;
- корзина из прототипа заменяется **проектом**: пользователь собирает комплект, ничего не «покупает».

### 3.3 Конвейер данных (предложение, первая итерация)

`tools/build_catalog.py`: читает `inventory/products.json`, `dealers.json`, тексты FAQ и презентацию и пишет в bundle `catalog-v2.json`, `showrooms.json`, `help.json`.

1. **Нормализация:**
   - покрытия «Глянцевая / Глянцевое» → `gloss`, «Матовая / Матовое / Матовый / Матовая эмаль» → `matte`;
   - технические поля привязываются к исполнению, если их порядок повторяет порядок вариантов (как у Aria); иначе остаются у изделия с пометкой.
2. **Категории** по `category_path`, плюс отдельная категория «Опции и кастомизация» (вырезы, отверстия, ниши, кронштейны): это не изделия, а модификации для проекта.
3. **Изображения:**
   - одна главная фотография на карточку, 1200 px по длинной стороне, HEIC или JPEG ~80–120 КБ;
   - превью 400 px;
   - ориентировочно 300 × ~110 КБ ≈ 30–35 МБ;
   - если локального файла нет — дозагрузка из публичного URL того же снимка с записью источника;
   - без изображения карточка показывает чертёжный силуэт категории, а не чужое фото.
4. **3D:** в bundle включаются только оптимизированные USDZ изделий, для которых строятся студия и цветовые этюды. Ориентир — 8–10 моделей, ~30 МБ: Noemi, Sofia 170, Mona 170, Alda 170, Ornella 170×75, Cascata 180×80, Ninfea, Luce, Greca уже есть. Fabia и Isola — только после оптимизации.
5. **Валидация (тесты):**
   - число карточек и категорий;
   - уникальность SKU;
   - у каждого варианта материал и покрытие из словаря;
   - цены положительные;
   - изображения существуют;
   - координаты дилеров в допустимых пределах;
   - телефоны нормализованы (UX-15);
   - снимок даты присутствует.

   **Ничего не выдумываем:** поле, которого нет в источнике, остаётся пустым и так и показывается.

## 4. Материалы: три визуальных варианта

Общая техника для всех трёх:
- SceneKit, PBR;
- окружение — **процедурная студийная HDR-карта**, генерируется кодом: белый циклорам, две-три прямоугольные софтбокс-полосы, тёмный flag для контраста;
- одна ключевая area-подобная направленная лампа с мягкой тенью и контактная тень-плоскость;
- `clearCoat` для Gelcoat;
- фон тёплый белый или графитовый, без glow и частиц;
- стекло только у элементов управления;
- Reduce Motion — без автоанимации.

Целевой бюджет — 60 fps на A17+:
- одна модель до 55 тыс. граней;
- карта окружения 1024 px;
- MSAA 4×;
- рендер на паузе вне экрана, как уже сделано для главной.

**Как различаются покрытия на одной геометрии:**

| | roughness | clearCoat | clearCoatRoughness | Примечание |
|---|---|---|---|---|
| S-Stone | ~0,55–0,65 | 0 | — | лёгкий микро-normal noise для «бархата» |
| S-Sense матовый | ~0,35–0,45 | 0,4 | 0,35 | |
| S-Sense глянец | ~0,08 | 1 | 0,03 | в полосе софтбокса видна чёткая отражённая форма |

Это **иллюстрация отклика на свет**, а не измеренные BRDF. Подпись об этом сохраняем.

### Вариант A — «Одна форма, две поверхности» (рекомендуемый базовый)

Noemi 170 из официальной USDZ на циклораме, ракурс 3/4 сверху. По изделию проходит вертикальный **шов сравнения**: слева S-Stone, справа S-Sense. Пользователь двигает шов пальцем, как разделитель «до / после», а второй жест ведёт софтбокс по дуге над изделием.

- **Реализация:** shader modifier поверхности. По мировой координате X выбираются `roughness`, `clearCoat` и цвет. Тонкая линия шва рисуется отдельно, на геометрии её нет.

**Плюсы:**
- самое прямое и честное сравнение: одна форма, один свет, разное только покрытие;
- реальное изделие, а не абстрактный образец;
- понятно без текста;
- один экран обслуживает и главную, и студию.

**Минусы:**
- на расстоянии всей ванны разница матового и глянцевого заметна в основном в бликах; на маленьком hero её нужно «поймать» светом. Отсюда вариант B;
- shader modifier требует проверки на симуляторе и устройстве.

### Вариант B — «Макро борта» (рекомендую для главной)

Камера вплотную к скруглённому борту Noemi: край чаши, внутренний радиус, линия перехода к корпусу. Широкая полоса софтбокса медленно (или по жесту) скользит вдоль борта.
- **S-Sense глянец:** узкое, резкое отражение полосы, в котором читается её форма.
- **S-Stone:** широкий мягкий градиент без отражённой формы.
- **Разрез:** кнопка «Структура» срезает борт плоскостью отсечения (clipping в shader modifier). Видно сечение:
  - S-Stone — однородная масса;
  - S-Sense — минеральная основа и отдельный слой Gelcoat **0,8 мм** с выноской размера.

**Плюсы:**
- самый «дорогой», журнальный кадр: крупная форма, свет, тишина;
- разница видна даже в маленьком блоке;
- разрез объясняет реальный факт (полнотелый против покрытия 0,8 мм).

**Минусы:**
- на макро может проявиться гранёность сетки — проверить сглаживание нормалей Noemi, при необходимости поднять сабдивизию только у борта или выбрать Sofia 170;
- масштаб слоя 0,8 мм на борту честно не виден — сечение показываем как увеличенную схему с подписью «масштаб условный».

### Вариант C — «Интерьерный разворот» (не рекомендую как основу)

Две официальные фотографии Salini (глянцевое и матовое изделие) в журнальном развороте, интерактивность — только в маленькой 3D-вставке.

**Плюсы:** настоящая фотография, минимальный риск, дёшево.

**Минусы:** разные изделия и разный свет — это сравнение интерьеров, а не материалов; повторяет сайт, а не добавляет того, чего на сайте нет.

### Рекомендация

**Главная — B, полная студия — A + B + применение к изделиям.**

**Главная**, большой журнальный блок высотой ~1,2 экрана:
- макро борта Noemi в тёплом белом циклораме;
- один крупный заголовок, например «Свет на камне»;
- подпись из двух строк с фактами состава;
- переключатель покрытия: «S-Stone · матовый / S-Sense · матовый / S-Sense · глянец»; варианты, недоступные для Noemi, неактивны с подсказкой «у этой формы нет»;
- жест по блоку ведёт свет;
- кнопка «Открыть студию».

**Полная студия материала:**
1. **Сравнение:** вариант A, шов и свет; выбор формы среди изделий с моделью; доступные исполнения — **строго по данным каталога**.
2. **Структура:** разрез B и короткие факты состава с источником.
3. **Цвет:** палитра RAL Classic выбранного материала.
   - Коды — из официальных PDF-палитр.
   - Цвет — стандартное sRGB-приближение RAL, с подписью «экранное приближение, сверяйте по физическому образцу».
   - Двухцветное исполнение (корпус / чаша) — только там, где позволяет модель (раздельные сетки). Иначе не предлагаем.
4. **Уход:** две колонки «можно / нельзя» из FAQ, Salini Fresco, гарантия по типу изделия.
5. **Применение:** «Изделия в S-Sense глянце» — список из каталога с ценами этого исполнения и кнопкой «в проект».

## 5. Подбор → проект → спецификация → персональное предложение PDF

### 5.1 Поток

1. **Подбор** — «Помочь выбрать»:
   - помещение и тип установки;
   - доступная длина (мм);
   - материал и покрытие;
   - бюджет;
   - срок: в наличии / можно подождать.

   Результат — **реальные карточки**, отсортированные по соответствию, с объяснением «почему подходит»: длина 1700 ≤ 1750, исполнение есть, цена в бюджете.
2. **Проект:**
   - имя проекта и клиента (локально);
   - помещения по желанию;
   - позиции с исполнением, цветом, опциями и количеством;
   - заметки.

   Опции кастомизации — отдельными строками «по запросу» и без цены, если её нет в источнике (UX-07).
3. **Спецификация:**
   - артикул, наименование, исполнение, цвет, количество, цена за единицу и сумма;
   - вес изделия и с упаковкой — для логистики;
   - класс срока;
   - итог с пометкой «цены публичного каталога на 06.10.2026, не оферта».
4. **Предложение** — PDF через `UIGraphicsPDFRenderer`; QuickLook и системное «Поделиться». Никаких отправок на сервер.

### 5.2 Структура PDF (A4, белая/графитовая вёрстка, шрифт системный)

1. **Обложка:** логотип Salini, название проекта, имя клиента и автора (роль: дизайнер / партнёр / покупатель), дата, крупное официальное фото главного изделия проекта.
2. **Состав в одном взгляде:** миниатюры позиций с исполнением и количеством.
3. **Польза выбранных изделий** — для каждого семейства 3–5 пунктов из официальных преимуществ: презентация 2026, тексты карточек. Если преимуществ в источнике нет — короткая сводка габаритов и исполнения **без** сочинённых формулировок.
4. **Материалы проекта** — только те, что реально выбраны: состав, структура (0,8 мм Gelcoat или полнотелый), уход, гарантия.
5. **Спецификация и стоимость:** таблица, итог, сроки по классам, оговорки.
6. **Цветовые этюды выбранного изделия** — главное изделие, выбранное пользователем:
   - **есть официальная USDZ:** офскрин-рендер **этой** модели в той же студии, 4–6 цветов — выбранный, белый, 2–4 цвета RAL, разрешённых для этого материала по палитре; одинаковый ракурс; подпись «концептуальная визуализация, не цветопроба»;
   - **модели нет** (раковина, мебель, зеркало): официальное фото в оригинальном цвете и рядом плашки выбранных RAL. **Фото не перекрашиваем** и Greca не подставляем;
   - мебель — отделки только из данных карточки, если они там есть.
7. **Дальше:**
   - где посмотреть: ближайшие экспозиции из данных дилеров;
   - официальные контакты;
   - QR и ссылки на карточки сайта.

Если позиций нет, PDF не создаётся. Тексты в PDF — только из модели данных, без генерации.

## 8. Salini Inside 2.0

### 8.1 Что показываем и как подписываем

**Заявления бренда:**
- 2 производственных комплекса;
- >12 000 м²;
- 1 роботизированный комплекс;
- 1500 изделий в месяц;
- >200 сотрудников;
- >1000 позиций.

**Генплан, расположение участков, посты, скорости, загрузка и исходы — условная демонстрация.** Это остаётся в постоянной подписи и в «О демонстрации».

### 8.2 Пространственная концепция (предложение)

- **Мир — два комплекса на одной карте**, разделённые городской дорогой:

  | | Комплекс A, «Минеральное литьё» | Комплекс B, «Обработка и комплектация» |
  |---|---|---|
  | Территория | крупнее | — |
  | Что внутри | сырьевой двор (силосы, IBC); линии литья ванн; литьё раковин и столешниц; поддоны | роботизированный участок; финиш и ОТК; упаковка; склад готовой продукции; комплектация мебели и зеркал; отгрузка |

  Межкомплексная логистика — шаттл-фуры с паллетами отливок по реальной дороге. Если Salini позже даст фактическое распределение участков, раскладка заменяется **данными**, а не перерисовкой кода.
- **Навигация:**
  - фиксированная истинная изометрия;
  - перемещение по земле, масштаб;
  - переключатель «Комплекс A / Комплекс B / Оба»: камера переезжает без поворота;
  - мини-карта с обоими комплексами и дорогой;
  - срез крыш.
- **Цепочки по семействам** — цвет маршрута и меток:

  | Семейство | Цепочка |
  |---|---|
  | ванны | смешивание → гелькоут (S-Sense) → крупные формы → отверждение → распалубка → роботизированная обработка → финиш → ОТК → обрешётка → склад |
  | раковины и столешницы | многоместные формы → отверждение → роботизированная обрезка и сверление → полировка → ОТК → короб |
  | поддоны | широкие плоские формы → обработка кромки → ОТК → паллета |
  | мебель и зеркала | приёмка от поставщиков → адресный склад → комплектация с раковинами → упаковка |

- **Движение со смыслом:**
  - каждый объект в движении принадлежит **модели**: заказ, партия, рейс, оператор, пост;
  - погрузчики возят конкретные партии между постами;
  - роботы работают, пока на посту есть изделие;
  - люди переходят между постами по сменному плану;
  - шаттл между комплексами уходит при наборе паллет;
  - декоративных бесконечных петель нет.
- **Визуальный язык:**
  - упрощённая, но выразительная архитектура;
  - тёплые белые фасады;
  - насыщенные, но **семантические** цвета: ванны — синий, раковины — бирюзовый, поддоны — терракотовый, мебель — ореховый, зеркала — серебристо-графитовый, решения и риски — янтарный;
  - асфальт и газоны из прошлой итерации;
  - больше воздуха между корпусами;
  - крупные читаемые станки;
  - объединение статики в один меш, общие материалы — опыт прошлого прохода.

### 8.3 Операционная модель

- Существующий `FactorySimulation` (сценарии Aria/F-04, Marea/ОТК/рейс 02) сохраняется без изменения результатов, на нём держатся тесты.
- Расширение: **поток партий по семействам и комплексам**. Узкие места вычисляются из очередей, а не задаются текстом. Решение пользователя меняет прогноз и движение.
- Новый сценарий для демонстрации связи комплексов:

  > Шаттл из A в B задержан → раковины Onda ждут обработки на роботизированном участке → решение «перенаправить на ручной финиш» или «ждать рейса» → видимое изменение срока заказа.

- Время, пауза и ускорение — по текущим правилам.

### 8.4 Риски

- Производительность при двух комплексах: объединение статики, отдельные узлы только у движущихся объектов, LOD по масштабу.
- Перегрузка кадра: слои и фокус на участке, подписи по приоритету.
- Не изображать WMS-реальное время: подпись «демонстрационная модель».

## 11. Техническая архитектура

- UIKit + SceneKit + MapKit + PDFKit/QuickLook, без внешних зависимостей. Локальные данные в bundle (JSON), пользовательские — в Application Support (Codable), вместо разрозненного `UserDefaults`.
- **Модули по файлам:**

  | Файл | Назначение |
  |---|---|
  | `CatalogData.swift` | модель и загрузка |
  | `CatalogSearch.swift` | нормализация и ранжирование |
  | `CatalogUI.swift` | список, фильтры, карточка |
  | `MaterialStudio2.swift` | сцена, шейдер, окружение |
  | `MaterialUI.swift` | главная и полная студия |
  | `ProjectStore.swift`, `ProposalPDF.swift` | проект и предложение |
  | `Showrooms.swift`, `Help.swift` | дилеры и помощь |
  | `Inside*` | расширение текущих файлов |

  Новые файлы добавляются через `project.yml` и `xcodegen` (по вашему процессу).
- **Офскрин-рендер этюдов:** `SCNRenderer` с той же студией и снимок в `UIImage` для PDF. Время генерации — секунды, с индикатором прогресса. Кэш по `sku + RAL`.
- **Тесты:**
  - валидация каталога;
  - поиск (SKU, раскладка, транслит);
  - фильтры;
  - доступность исполнений студии по данным;
  - сборка PDF (страницы, суммы равны спецификации, этюды только для модели выбранного изделия);
  - детерминизм Inside и существующие сценарии;
  - производительность построения сцены.
- **Размер:** сейчас Resources ~90 МБ (ролики). План: +30–35 МБ фото, +25–30 МБ USDZ. Ролики V2 из bundle уже исключены; проверить, не попадают ли лишние постеры.
