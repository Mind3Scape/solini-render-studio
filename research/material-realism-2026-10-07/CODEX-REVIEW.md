## Verified primary sources

- Three.js physical material: https://threejs.org/docs/pages/MeshPhysicalMaterial.html — a separate coat and its own roughness/normal; normal and roughness textures contain data, not sRGB color.
- Color management: https://threejs.org/manual/pages/color-management.html — linear rendering and explicit input/output spaces.
- Three.js WebGPU renderer: https://threejs.org/docs/pages/WebGPURenderer.html — WebGPU with WebGL2 fallback, half-float default output buffer.
- WebKit: https://webkit.org/blog/17640/webkit-features-for-safari-26-2/ — WebGPU shipped in Safari 26. Availability alone does not establish scene fidelity or frame rate.
- Path tracing: https://github.com/gkjohnson/three-gpu-pathtracer — current main requires WebGPU; progressively accumulates samples. Do not promise convergence in 1–2 seconds without a measured device run.
- Babylon.js features: https://www.babylonjs.com/specifications/ — PBR, HDR IBL, clear coat, area lights, shadow/GI options.
- Filament algorithms: https://google.github.io/filament/main/filament.html — dielectric BRDF, energy conservation, IBL, normal mapping, occlusion, exposure pipeline. A design reference, not a dependency chosen for this pass.
- Apple SCNMaterial: https://developer.apple.com/documentation/scenekit/scnmaterial — native clear coat, normals and ambient occlusion exist; the API is deprecated, so engine migration remains longer-term work.
- HDRI candidate: https://polyhaven.com/a/studio_small_09 — actual unclipped studio HDRI by Sergej Majboroda.
- License: https://polyhaven.com/license — assets CC0, allowed in distributed commercial apps. Preserve attribution/provenance anyway.

## Opus implementation brief

1. Replace live LDR environment with real linear HDR radiance (bundled 2K CC0 studio HDRI preferred; robust floating-point loading, cached resources). Reduce unoccluded ambient wash. Physically coherent directional/key/contact shadows and restrained textured floor. White must retain inner-bowl gradients; dark RAL must remain readable.
2. Add subtle scale-aware finish-specific micro-normal and roughness variation. S-Stone must look honed/satin, not grainy granite. S-Sense has a smooth separate Gelcoat lobe. No metallic parameters on mineral surfaces. Do not recolor metal drains/supports blindly if separable in official mesh.
3. Preserve legal finish availability, registered form framing, AX/Reduce Motion/offscreen rendering behavior. Avoid introducing hitches on main-thread generation. Keep proposal PDF quality at least as good; if live and print need different presets, make this explicit and test it.
4. Build a repeatable visual comparison harness for Noemi and Greca, whole/macro, white/green/dark; do not claim quality from parameter-only tests. Add meaningful checks for texture/HDR loading and material lifecycle. Build-for-testing; Codex owns simulator.
5. Freeze for visual review. Do not change build number, commit or upload; Codex owns release.
